# Tailoring rules

1. Start from the user's base resume file every time; never from a previous tailored copy.
2. Headline: `<role-matched title> | <strongest proof for this role> | <signature credential>` using claims only.
3. Summary: 3 to 4 sentences mirroring the posting's top 3 requirements, each answered with a true, sourced fact.
4. Reorder competencies and bullets so the most relevant come first. Remove, never invent.
5. Keep dates, titles, employers and degrees exactly as in `claims.yaml`.
6. Respect `never_say`. No em dashes unless the voice file allows them.
7. Location line exactly as `claims.yaml` person.public_location.
8. Open questions ("Why this role?"): 80 to 150 words, specific to the company, from claims and the messaging kit.
9. Salary questions: the floor or the posted minimum, whichever is higher, unless the user set a different rule.
10. Voluntary self-identification questions: "Decline to self-identify" unless the user set otherwise.
11. File name: `<Full Name> Resume - <Company>.<ext>`.
